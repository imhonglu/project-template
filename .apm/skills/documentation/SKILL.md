# 문서 작성·정제

독자가 판단하고 실행할 정보만 남깁니다. 문서 작성 요청만으로 구현·계약을 바꾸지 않습니다.

## 근거 확인

요청·기존 문서에서 독자와 작업을 파악하고 다음 근거를 읽습니다. 도구·저장소에도 없는 필수 정보만 질문합니다.

| 설명할 내용      | 대조할 근거                     |
| ---------------- | ------------------------------- |
| 사용법·지원 범위 | 공개 API·명령·설정·테스트       |
| API 주석·예제    | 선언·구현·호출부·동작 테스트    |
| 설계·선택 이유   | 요구사항·논의·현재 구현         |
| 작업 지침        | 적용할 작업·실제 절차·기존 관례 |

사실·가정·제안·미확인을 구분하고, API 보장과 프로젝트 관례를 구별합니다. 근거가 충돌하면 위치와 차이를 보고하며 기본값·지원 범위·실패 동작을 임의로 확정하지 않습니다.

## 정보 배치

표현만 수정하면 기존 제목·절 순서를 유지합니다. 구조를 바꿀 때는 독립 주제를 제목으로, 순서를 번호 목록으로, 같은 기준의 비교를 표로 나눕니다. 예제·긴 조건은 소제목 아래로 펼칩니다.

| 문서                | 정보 순서·위치                                   | 상세 예제                                               |
| ------------------- | ------------------------------------------------ | ------------------------------------------------------- |
| 프로젝트 시작 안내  | 소개 → 최초 실행 → 관련 안내                     | [루트 README](references/readme.md#루트)                |
| 패키지 사용 안내    | 소개 → 사용법 → 개발·제약                        | [패키지 README](references/readme.md#패키지)            |
| API 계약            | 소유 선언에 계약, 사용 안내에 조합 절차          | [주석 위치](references/api-contracts.md)                |
| 절차·작성 기준      | 적용 조건 → 행동·예제 → 성공 기준                | [구조 선택](references/document-structure.md#구조-선택) |
| 설계 제안·결정 기록 | 문제·제약 → 제안·근거 → 대안·확인 방법·결정 상태 | [설계안](references/document-structure.md#설계안)       |
| PR 설명             | 변경 이유 → 최종 변경 → 검증·제약                | [PR 설명](references/document-structure.md#pr-설명)     |

명령 앞에는 작업 디렉터리·필수 설정·입력과 파일 변경·외부 요청 같은 실행 효과를, 뒤에는 성공 결과와 알려진 실패 대응을 둡니다. 비밀값 대신 제공 방법을 씁니다.
예제의 실행 가능 여부가 모호하면 발췌·템플릿·제안·모의 응답·타입 검사 전용임을 표시하고 생략한 구현을 밝힙니다.

### 삭제·유지·이동 기준

- **삭제:** 제목·선언·예제가 이미 전달하는 설명, 행동이나 판단을 바꾸지 않는 일반론, 앞의 내용을 되풀이하는 요약.
- **유지:** 코드로 알 수 없는 단위·기본값·실패 후 상태·완료 시점·승인·예외·소유권.
- **이동:** 다른 작업의 상세 규칙은 해당 정본에 두고 링크나 적용 예로 연결. 실행에 필요한 조건은 사용 단계에도 남김.

예제 앞뒤에 코드를 줄마다 해설하지 않습니다. 삭제 기준의 [적용·제외 예제](references/document-structure.md#중복과-계약-구분)를 대조합니다. 문장 수·글자 수로 삭제 여부를 정하지 않습니다.

## 정본 갱신

API 설명은 선언·구현·테스트로 확인한 계약을 담고, 태그·참조는 해당 언어의 문서 주석 문법을 따릅니다.
설명은 한 곳에서 관리하고 버전·설정 전체는 관리 파일로 연결합니다. 변경된 계약의 준비 조건·예제·기대 결과·제약·문제 해결·이전 안내를 함께 갱신합니다.

작업 기록까지 정리한다면 현재 동작·선택 이유는 사용 안내·설계에, 미완료 작업은 계획에, 재현 근거는 리비전·환경·미확인 범위와 함께 검증 기록에 둡니다. 중간 기록은 정본으로 옮겼고 삭제가 허용됐을 때 제거합니다.

## 확인

사용 안내는 준비 → 실행 → 결과·실패 대응 순서로 따라갑니다. 지침은 적용·제외 사례로, 설계안은 같은 제약에서 대안을 고를 기준으로 확인합니다. 원문과 계약·금지·승인·예외·수치가 같은지도 대조합니다.

| 변경                | 확인 방법                                                                       |
| ------------------- | ------------------------------------------------------------------------------- |
| 문서·링크           | 표시·링크·철자, 제목·목록·강조·HTML 힌트 보존                                   |
| 실행·타입 전용 예제 | 실행 예제는 타입 검사와 실행, 타입 전용은 타입 검사                             |
| 구조·계약 제안      | 명시한 전제·대안·판단 기준 대조                                                 |
| 표현만 수정         | 원문과 의미 대조; 이 작업만을 이유로 제품 빌드·배포·전체 테스트를 추가하지 않음 |

저장소에서 별도로 요구하는 검사는 따릅니다. 외부 서비스·데이터를 바꾸는 예제는 허용된 격리 환경에서 검증합니다.
실행한 도구·대상·결과와 미실행 이유·미확인 계약을 보고합니다. 확인 범위를 실제 독자의 성공이나 다른 환경의 보장으로 넓히지 않습니다.

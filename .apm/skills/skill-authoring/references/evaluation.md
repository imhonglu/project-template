# 스킬 선택·행동·효율 평가

## 평가 범위

| 확인할 변경                        | 검증                                                             |
| ---------------------------------- | ---------------------------------------------------------------- |
| 이름·문장·파일 이동                | 메타데이터, 링크·앵커, 참고 문서 도달 가능성, 의미 보존          |
| 선택 설명·스킬 경계                | 실제 요청과 후보 이름·설명만 제공하고 선택한 본문·참고 문서 확인 |
| 절차·예제·완료 조건                | 대표 요청·최소 입력·대상 스킬만 제공해 산출물·행동 검사          |
| 도구 호출·토큰·시간·비용 개선 주장 | 같은 조건의 변경 전후 실행과 원시 기록 비교                      |

스킬 이름을 직접 지정한 실행으로 선택 정확도를 주장하지 않습니다. 카탈로그를 직접 제공했다면 제품의 스킬 설치·자동 발견 검증과 구분합니다. 보조 스킬을 함께 읽었다는 사실만으로 오선택으로 판정하지 않고 요청과의 관련성을 봅니다.

## 실행 전에 고정할 것

- 변경 전후 스킬·참고 문서·주입할 지침을 재현할 리비전 또는 사본·해시. 미커밋 변경도 포함
- 동일한 요청·입력·의존성·도구·환경·권한, 모델·추론 수준·서비스 등급·시간 제한
- 필요한 정상·예외·범위 밖 사례, 결과 품질과 행동의 판정 항목
- 반복 횟수·실행 순서·병행 수, 사용량 단위와 비용 환산 단가

현재 요청에 필요한 사례부터 고릅니다. 같은 작업의 전후에는 같은 조건을 쓰고, 전후 순서를 교대합니다. 새 세션·격리된 작업 공간에 과제와 필요한 스킬만 제공하며 정답·채점표·이전 결과는 제외합니다. 실행 중 기준은 고정하고 실패 결과도 보존합니다. 추가 수정은 다음 후보로 분리합니다.

## 판정과 사용량

품질은 실제 산출물·계약·검사 결과로, 행동은 선택한 지침·도구 기록·수정 범위·권한 보존으로 판단합니다. 구조 검사만으로 실제 작업 성공을 보고하지 않습니다.

| 지표      | 기록·해석                                                                      |
| --------- | ------------------------------------------------------------------------------ |
| 선택      | 필요한 담당 선택 여부, 함께 읽은 스킬·참고 문서와 그 이유                      |
| 품질·행동 | 항목별 충족·미충족·미확인과 근거. 채점자·블라인드 여부도 기록                  |
| 도구 호출 | 완료된 도구 이벤트 수. 묶은 셸 명령은 한 호출이므로 실제 조회·변경 범위도 확인 |
| 토큰      | 누적 입력·캐시 입력·출력. 출력에 포함된 추론 토큰을 중복 합산하지 않음         |
| 시간      | 각 실행의 실제 경과 시간. 병행 실행의 합계와 전체 대기 시간을 구분             |
| 비용      | 실제 청구액이 있으면 사용. 없으면 명시한 단가의 환산액으로 표시                |

평가 기록은 사용한 리비전·사본, 과제·조건, 원시 로그와 항목별 판정을 연결합니다. 발견한 회귀 입력은 다음 사례로 남깁니다.
시간 초과·사용량 누락은 0원·0토큰으로 처리하지 않습니다. 캐시·서버 부하·도구 오류 복구와 변경하지 않은 스킬의 편차를 함께 봅니다. 단일 실행의 차이를 일반화하지 않습니다. 차이가 작거나 엇갈리면 미확인으로 남기고, 일반화가 필요할 때 반복·다른 사례를 추가합니다. 품질 저하를 낮은 비용으로 상쇄하지 않습니다.

## Codex CLI 기록 집계

이미 실행한 CLI의 JSON 이벤트와 결과 파일은 [집계 스크립트](../scripts/summarize-evaluation.py)로 요약할 수 있습니다. 모델 실행·네트워크 요청·파일 수정은 수행하지 않고 집계 JSON을 표준 출력으로 냅니다.

준비할 manifest의 `runs[].path`는 manifest 위치 기준이며, 각 실행 폴더에는 `events.jsonl`과 `result.json`이 있어야 합니다. 결과에는 `elapsed_seconds`·`exit_code`·`timeout`을 기록합니다. 식별자·비교 버전·과제는 manifest에 둡니다.

```json
{
  "rates_per_million": { "input": 10, "cached_input": 1, "output": 50 },
  "runs": [
    { "id": "before-case-1", "variant": "before", "case": "case-1", "path": "runs/before-case-1" },
    { "id": "after-case-1", "variant": "after", "case": "case-1", "path": "runs/after-case-1" }
  ]
}
```

단가는 계산 형식의 예이며 현재 가격을 뜻하지 않습니다. 비용 비교에는 양쪽에 같은 명시적 단가를 적용하고, 단가를 생략하거나 별도 캐시 쓰기 토큰의 단가가 없으면 비용은 `null`입니다.

스킬 디렉터리에서 실행합니다.

```sh
python3 scripts/summarize-evaluation.py /absolute/path/evaluation.json
```

`measurement_complete: true`인 실행끼리 수치를 비교합니다. 형식 오류는 종료 코드 1과 오류 메시지로 보고합니다. 이 스크립트는 선택·품질을 자동 채점하지 않으며, 실행 환경이 같은지도 별도로 확인해야 합니다.

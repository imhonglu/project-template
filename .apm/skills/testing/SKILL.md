# 테스트 작성

기존 테스트 도구와 실행 환경을 사용합니다. 아래 API 예제는 Vitest 기준입니다.

## 사용 시점

- 유닛 검증: "이 함수의 경계값과 오류 사례를 테스트해줘"
- 회귀 테스트: "이 버그가 다시 발생하지 않도록 테스트를 추가해줘"
- 통합 검증: "저장한 데이터를 다시 조회하는 흐름을 테스트해줘"
- 브라우저 검증: "수량 버튼을 누르면 합계가 바뀌는지 확인해줘"
- 실패 분석: "실패하는 테스트의 원인을 찾아 고쳐줘"

## 작업 절차

### 범위·파일 선택

요구사항에서 정상·경계·실패 사례를 고르고, 검증 범위와 실행 환경을 정합니다. 작성할 범위에 맞는 예제를 읽고, 같은 동작을 반복 검증하는 사례는 줄입니다.

| 확인할 동작                  | 파일명 예                        | 읽을 예제                                      |
| ---------------------------- | -------------------------------- | ---------------------------------------------- |
| 계산·분기·상태 전이          | `shipping-fee.test.ts`           | [유닛 테스트](references/unit-tests.md)        |
| 저장·조회, 모듈·DB·HTTP 연동 | `note-store.integration.test.ts` | [통합 테스트](references/integration-tests.md) |
| DOM·이벤트·브라우저 API      | `cart-counter.browser.test.ts`   | [브라우저 테스트](references/browser-tests.md) |

- 테스트는 대상 소스 가까이에 둡니다. 파일명은 소스 이름에 테스트 접미사를 붙이며, 유형 표시는 구분이 필요할 때만 추가합니다.
- `.ts`·`.tsx`·`.test`·`.spec` 등 확장자·접미사는 코드 형식과 실행 도구에 맞춥니다.
- 브라우저는 유닛·통합 테스트에서도 사용하는 실행 환경입니다. 접미사만으로 환경이 바뀌지 않으므로 실행 설정의 포함·제외 범위를 확인합니다.

### 준비·격리

- 검증하는 경계는 실제 구현을 사용하고, 범위 밖 의존성은 필요할 때 대체합니다. 시간·난수는 고정값으로 통제합니다.
- 입력 객체와 모킹 상태를 테스트 간 격리합니다. 중첩 객체·배열도 공유하지 않습니다.
- 반복되는 입력 준비는 새 객체를 반환하는 팩터리로 추출하고, 테스트마다 달라지는 값은 호출부에 남깁니다.
- DB·파일·포트는 테스트별 자원을 할당하고 종료 시 정리합니다.
- 실행 환경과 API가 지원하고 자원 수명이 테스트 콜백 안에서 끝나면 `using`·`await using`을 사용합니다. 그 밖의 자원은 생성 직후 사용 수명에 맞는 정리 훅을 등록합니다.
- `concurrent`는 공유 상태를 바꾸지 않는 테스트에만 사용하고, 단언에는 콜백의 `{ expect }`를 사용합니다. 전역 모킹·가짜 시계를 변경하는 테스트는 함께 실행하지 않습니다. [동시 실행](https://vitest.dev/guide/parallelism.html#test-parallelism)

외부 의존성을 대체하거나 시간을 고정할 때 [모킹 예제](references/mocking.md)를 읽고, 변경한 항목에 맞춰 복구합니다.

### 작성·단언

[유닛 테스트 예제](references/unit-tests.md)의 `shipping-fee.ts`를 검사하는 최소형입니다. 경계·실패 사례는 참고 문서의 테스트로 확장합니다.

```ts
// shipping-fee.test.ts
import { expect, it } from "vitest";

import { getShippingFee } from "./shipping-fee.ts";

it("무료 배송 기준에 도달하면 배송비가 없습니다", () => {
  const orderTotal = 30_000;

  const fee = getShippingFee(orderTotal);

  expect(fee).toBe(0);
});
```

- `describe`는 대상, `it`은 조건과 결과를 나타냅니다. 준비·실행·검증은 빈 줄로 구분합니다.
- 같은 흐름의 입력별 검증은 `it.each`, 테스트 컨텍스트도 필요하면 `it.for`를 사용합니다. 서로 다른 시나리오는 별도 `it`로 나누되 한 동작의 단언은 함께 둡니다.
- 호출자가 사용하는 인터페이스에서 동작을 검증합니다. 기대값은 요구사항에서 구하며, 구현의 수식을 다시 계산하거나 실제 출력을 그대로 복사하지 않습니다.

| 항목           | 컨벤션                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------ |
| 원시값·동일성  | `toBe`; 객체·배열의 정확한 구조는 `toStrictEqual`                                          |
| 부분 계약      | 관심 있는 공개 필드만 검증할 때 `objectContaining`                                         |
| 오류           | 동기 `expect(() => run()).toThrow(...)`; 비동기 `await expect(run()).rejects.toThrow(...)` |
| 비동기 결과    | `resolves`·`rejects`·브라우저 단언과 사용자 조작은 `await`                                 |
| 상태 변화 대기 | 완료 Promise는 직접 `await`; 관찰해야 하는 상태는 `await expect.poll(...)`                 |
| 호출 검증      | 외부 API에 전달할 값처럼 호출 자체가 계약일 때 `toHaveBeenCalledWith`                      |
| 타입 검증      | 일반 테스트 파일에 `expectTypeOf`를 함께 작성하고 프로젝트의 `typecheck`로 검사            |
| 스냅샷         | 작고 안정적인 출력에 사용하며 갱신 시 차이를 직접 검토                                     |

`expect.poll`의 콜백은 조회만 수행합니다. 클릭·생성·저장 같은 동작을 넣으면 재시도마다 반복됩니다. 브라우저 화면은 `expect.element`로 기다립니다. [상태 단언](https://vitest.dev/api/expect.html#poll)

제네릭 추론 등 공개 타입 계약을 검증할 때 [타입 테스트 예제](references/type-tests.md)를 읽습니다.

테스트의 이름·호출·단언을 사용 예로 삼고, 주석에는 설정 이유나 실행 제약을 적습니다.

공개 구현·재사용 도우미의 입력·반환·오류 계약은 TSDoc으로 설명합니다. 관련 타입·함수는 `{@link}`·`@see {@link ...}`로 연결합니다.

### 실패 수정

- 실패하면 입력·기대값·구현을 비교합니다. 요구사항이 바뀐 경우 기대값을 갱신하고, 버그인 경우 재현 테스트와 구현을 수정합니다.
- 통과만을 위한 단언 완화·무조건적인 스냅샷 갱신·임의 대기·재시도·`skip`은 추가하지 않습니다.

## 결과 확인

- 예제의 구현·테스트는 표시된 파일명으로 같은 디렉터리에 두고 해당 프로젝트에서 검사합니다.
- 프로젝트의 `test`·`typecheck` 스크립트로 검증하고, 테스트 파일도 타입 검사 대상에 포함됐는지 확인합니다.
- 최종 검증은 `check`를 사용하며, 전체 검사에 포함된 단계는 중복 실행하지 않습니다.
- 커버리지 보고서가 있으면 변경한 분기·오류 경로와 실제 단언을 대조해 누락을 확인합니다.
- 회귀 테스트는 수정 전 실패·수정 후 통과를 확인하고, 실행한 환경·결과·미실행 범위를 보고합니다.

# 실행 비교를 통한 지침 개선

같은 과제의 실행 결과로 문제를 찾고 기존 지침을 정제합니다. 비교만 요청받았다면 변경 후보까지 제시합니다.

## 비교 조건

문제가 관찰된 요청과 지침에서 확인할 효과를 정합니다. 기존 과제·입력·판정 기준·실행기·기록·집계 도구를 재사용하고, 새 후보만 추가로 고정합니다.

| 확인할 효과    | 수행 에이전트에 제공할 것                              |
| -------------- | ------------------------------------------------------ |
| 스킬 선택      | 실제 요청과 후보 이름·설명; 선택한 본문·참고 문서 확인 |
| 작업 품질·절차 | 대표 요청·최소 입력·평가할 지침                        |

스킬의 필요성·통합·삭제를 판단할 때는 스킬이 없는 조건도 비교합니다. 이때 필수 정책과 사용자 요구는 유지합니다.

직접 지정한 실행은 선택 평가가 아닙니다. 카탈로그 선택과 제품의 설치·자동 발견도 구분합니다. 보조 스킬 열람은 요청과의 관련성으로 판단합니다.

전후에 다음 조건을 맞춥니다.

- 대상 저장소·스킬·참고 문서·주입 지침의 리비전 또는 사본·해시. 미커밋 변경 포함
- 요청·입력·의존성·도구·권한, 모델·추론 수준·서비스 등급·시간 제한
- 필요한 정상·예외·범위 밖 사례와 품질·행동 기준, 반복 횟수·순서·병행 수
- 사용량 단위와 같은 비용 환산 단가

기존 기록은 위 조건을 확인해 사용합니다. 기록이 없으면 이전본부터 실행합니다. 이전본·환경·측정값이 없으면 해당 효과는 미확인으로 남깁니다.

## 근거 확인과 정제

제공된 요청·지침·도구 사용법과 관찰할 행동에 필요한 기록부터 읽습니다. 독립 조회는 묶고, 확보한 근거를 재사용합니다. 도구 구현은 사용법으로 계약이나 실패 원인을 확인할 수 없을 때 읽습니다.

1. 관찰한 문제 하나를 가설로 좁히고 해당 문장·예제·배치를 고칩니다. 필요한 조건은 기존 지침에 합치고 필수 검사·권한·예외는 유지합니다.
2. 새 실행은 같은 조건의 새 세션·격리 공간에서 수행합니다. 정답·채점표·이전 결과는 수행 에이전트에게 주지 않습니다. 반복 시 전후 순서를 교대하고 실패도 남깁니다. 추가 수정은 다음 후보로 분리합니다.
3. 양쪽 실행이 끝나면 아래 근거와 변경 지침의 메타데이터·링크·계약을 묶어 대조합니다. 계산·검사 결과를 판정에 재사용하고, 누락·실패·추가 수정 범위만 다시 확인합니다. 배포본은 대상 환경의 절차로 재생성합니다.

| 판단 | 대조할 근거                                                |
| ---- | ---------------------------------------------------------- |
| 수치 | 집계 결과; 누락·불일치가 있으면 해당 원시 사용량·종료 기록 |
| 품질 | 사전 기준·산출물·실제 검사 결과·초기/종료 상태             |
| 행동 | 관찰할 행동에 해당하는 명령·결과·변경                      |

Codex CLI 수치는 [집계 도구](references/codex-cli.md)의 사용법에 따라 계산합니다.

## 판정과 보고

| 결과                                      | 처리                                                |
| ----------------------------------------- | --------------------------------------------------- |
| 필수 품질을 유지하며 요청한 문제가 해결됨 | 변경 유지. 효과를 확인한 과제·조건 명시             |
| 품질·권한·검증 범위가 나빠짐              | 후보를 다시 정제하고 같은 기준으로 재평가           |
| 조건이 다르거나 수치가 누락·엇갈림        | 효과 미확인. 일반화가 필요할 때 반복·다른 사례 추가 |

품질 저하를 낮은 비용으로 상쇄하지 않습니다. 시간 초과·사용량 누락을 0원·0토큰으로 계산하지 않습니다. 성공한 실행만으로 결론 내리지 않습니다. 캐시·서버 부하·오류 복구 등 확인 가능한 편차를 함께 보고 단일 실행의 차이를 일반화하지 않습니다.

보고서는 판정·비교표·바뀐 지침·남은 제약으로 끝냅니다. 통과 항목의 상세, 실행 조건·해시·계산식은 원시 기록으로 연결합니다. 본문에는 판정을 바꾸는 차이·실패·미확인 범위만 남깁니다.

```md
판정: <유지·재수정·미확인과 이유>

| 지표                     | 이전                   | 후보                          |
| ------------------------ | ---------------------- | ----------------------------- |
| 품질·필수 검증           | <충족/전체; 근거 링크> | <충족/전체; 실패 항목과 근거> |
| 도구 호출·토큰·시간·비용 | <측정값>               | <측정값>                      |

변경: <문제 → 바꾼 지침 → 관찰한 행동 차이>. <근거 링크>.
제약: <남은 실패·미확인 범위>. <조건·원시 기록·채점 근거 링크>.
```

호출은 완료된 도구 이벤트 수로, 묶은 셸 명령은 한 호출로 셉니다. 토큰은 누적 입력·캐시 입력·출력을 구분합니다. 출력에 포함된 추론 토큰은 다시 더하지 않습니다. 시간은 실행별 경과 시간입니다. 병행 실행의 합계와 전체 대기 시간을 구분합니다. 비용은 실제 청구액 또는 단가를 밝힌 참고 환산액입니다. 대상 실행과 평가 운영·채점의 사용량을 구분합니다.

발견한 회귀 입력은 다음 평가 사례로 남깁니다. 모델·환경이 바뀌면 기존 효과를 그대로 적용하지 않고 관련 사례로 다시 확인합니다.

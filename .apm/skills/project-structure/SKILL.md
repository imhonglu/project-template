# 도메인 중심 구조 설계

요구사항·실제 업무 흐름·용어와 기존 코드의 책임을 대조합니다.
같은 업무 규칙과 상태 변경을 함께 관리할 범위를 도메인 경계로 정합니다.

## 책임 배치 예제

주문·결제·배송의 규칙과 상태를 소유 책임에 따라 나누는 예제입니다.

```text
orders/
├── checkout/       # 주문 확정 조건·금액 계산
└── cancellation/   # 취소 조건·주문 상태 변경·환불과 배송 중단 요청
payments/           # 결제 승인·환불 조건과 결제 상태
shipping/           # 출고 조건과 배송 상태
```

주문 취소 흐름은 결제·배송 도메인이 제공하는 판단·처리 결과를 이용합니다.
각 도메인의 상태 변경은 해당 소유자가 수행합니다.

## 작업별 기준

### 경계와 공통화

| 확인한 관계                                          | 처리                          |
| ---------------------------------------------------- | ----------------------------- |
| 같은 업무 규칙·불변 조건·상태 변경을 함께 관리       | 같은 도메인에 배치            |
| 용어·자료형은 같아도 업무 의미·규칙·변경 이유가 다름 | 도메인별 계약 유지            |
| 여러 업무 흐름에서 같은 의미·규칙이 반복             | 계약의 소유자를 정하고 재사용 |

공통화는 사용처 수보다 업무 의미와 변경 이유를 기준으로 판단합니다.
새 계층·공통 영역은 독립된 책임이 확인될 때 추가합니다.

### 의존 방향과 연동

| 책임                          | 소유 위치                         |
| ----------------------------- | --------------------------------- |
| 업무 계산·검증·상태 전이      | 해당 도메인                       |
| 여러 도메인을 잇는 업무 흐름  | 그 흐름을 맡은 도메인의 조정 역할 |
| 저장·외부 서비스의 자료 변환  | 도메인과 외부 시스템의 연결 경계  |
| 화면 문구·응답 형식·전달 방식 | 각 소비자 경계                    |

도메인 간 요청은 소유자가 제공하는 계약으로 연결합니다. 입력·결과·실패의 업무적 의미와 상태 변경 책임을 정합니다.
외부 시스템의 자료 구조·상태값은 연결 경계에서 도메인의 용어로 변환합니다.
순환 의존성이 생기면 업무 흐름의 조정 책임과 각 도메인에 남을 규칙을 다시 구분합니다.

### 기존 경계 변경

기존 소비자와 보존할 데이터를 기준으로 변경 방법을 정합니다.

| 조건                                                 | 처리                                              |
| ---------------------------------------------------- | ------------------------------------------------- |
| 모든 소비자를 함께 바꿀 수 있고 데이터도 재생성 가능 | 현재 계약으로 정리하고 변경 영향·초기화 방법 안내 |
| 사용자 데이터 또는 구버전 소비자가 남음              | 변환·호환 기간·실패 시 복구 방법 설계             |
| 데이터 소유자·복구 가능성이 불명확                   | 읽기 전용으로 확인하고 삭제·초기화 보류           |

호환 코드에는 대상과 제거 조건을 정합니다. 데이터 변환 후 소비자의 실제 업무 흐름을 검증합니다.

## 결과 확인

- 대표 업무 흐름에서 규칙의 소유자·호출 방향·상태 변경 책임을 추적합니다.
- 같은 규칙의 중복 구현과 다른 도메인의 내부 상태에 대한 직접 의존을 확인합니다.
- 분리·공통화의 근거와 기존 소비자·데이터에 미치는 영향을 남깁니다.
- 구조를 바꾸면 정상·실패 흐름과 보존할 데이터를 이전 계약과 대조합니다.
- 검증 결과와 미확인 조건·남은 제약을 보고합니다.

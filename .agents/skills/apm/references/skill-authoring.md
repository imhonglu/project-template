## 정보 배치

| 위치            | 담을 정보                                                           |
| --------------- | ------------------------------------------------------------------- |
| `name`          | 스킬 식별자                                                         |
| `description`   | 선택에 필요한 대상·수행할 작업·사용 상황                            |
| `SKILL.md` 본문 | 공통 실행 조건·기본 절차·판단 기준·완료 조건                        |
| `references/`   | 특정 조건에서 필요한 상세 예제·절차; 본문에서 읽을 조건과 경로 연결 |

스킬 선택에는 [먼저 제공되는 이름·설명](https://agentskills.io/specification#progressive-disclosure)을 사용합니다.
본문의 `사용 시점`은 설명에 없는 적용 조건이 필요할 때 둡니다.

## 본문 템플릿

### 예제와 판단 기준

예제와 작업별 기준을 함께 제공할 때 사용합니다. 대괄호·스킬명·참고 파일 경로는 실제 내용으로 바꾸고, 필요한 절을 선택·조합합니다.

````markdown
---
name: task-name
description: "[대상]을 [수행할 작업]합니다. [사용 상황·대표 요청]에 사용합니다."
---

# [작업 이름]

[작업 전에 확인할 구현·환경과 공통 실행 조건]

## 기본 예제

전제: [실행 위치·필수 설정·선행 파일]

```text
[입력·실행·결과가 드러나는 대표 예제]
```

[예제에서 드러나지 않는 이유·제약]

## 작업별 기준

### [판단이 필요한 작업]

[기본 처리 방식과 선택이 달라지는 조건]

[특정 조건]이면 [상세 예제](references/task-example.md#변형)를 읽습니다.

## 결과 확인

- [결과와 실제 요구사항·구현·계약을 대조할 항목]
- [대상 환경에서 실행할 검사와 성공 판단 기준]
- [변경·검증 결과와 미실행 범위·남은 제약]
````

### 작업별로 찾아 읽는 예

APM의 검색·설치·연결을 요청별로 안내하는 구조 예제입니다.

```markdown
# 스킬·도구 관리

## 작업 선택

| 요청                  | 읽을 절                     |
| --------------------- | --------------------------- |
| 작업에 맞는 스킬 찾기 | [스킬 검색](#스킬-검색)     |
| 선택한 패키지 설치    | [패키지 설치](#패키지-설치) |
| 외부 서비스 연결      | [MCP 연결](#mcp-연결)       |

## 스킬 검색

필요한 기능으로 후보를 찾고 원본의 지원 범위·실행 조건을 비교합니다.

## 패키지 설치

설치할 패키지·배포 대상을 확인하고 선언·잠금 파일·생성물을 함께 갱신합니다.

## MCP 연결

서버의 제공 방식·인증·권한을 확인하고 대상 도구에서 연결을 검증합니다.
```

## 개선점의 소유권

| 개선 내용                                               | 소유자                                   |
| ------------------------------------------------------- | ---------------------------------------- |
| 스킬 선택 조건·본문과 참고 파일의 역할·스킬 분리        | `apm`                                    |
| 문장 정제·문서의 정보 구조·일반 예제 구성·Markdown 표기 | `documentation`                          |
| 구현·테스트·언어별 주석 문법                            | `typescript`·`testing` 등 해당 작업 스킬 |
| 특정 저장소에 고정된 경로·설정·운영 정책                | 저장소 규칙·설정·소유 패키지 문서        |
| 특정 작업의 단계·임시 경로·일회성 승인                  | 해당 작업 기록                           |

규칙은 소유 스킬에서 정의하고, 다른 스킬의 예제에는 적용 결과만 보여줍니다.

## 스킬 경계 조정

| 사용 중 확인한 문제                   | 조정할 곳                                           |
| ------------------------------------- | --------------------------------------------------- |
| 필요한 요청에서 스킬을 선택하지 못함  | `description`의 대상·작업·상황                      |
| 범위 밖 요청에도 스킬이 선택됨        | `description`을 좁히고 범위 밖 지침 제거            |
| 특정 조건의 상세 내용이 본문을 차지함 | 같은 스킬의 `references/`로 분리하고 읽을 조건 연결 |
| 서로 다른 작업이 한 스킬에 섞임       | 적용 범위·절차·검증이 독립적이면 별도 스킬로 분리   |

각 스킬은 다른 스킬·특정 저장소 문서를 필수로 읽지 않아도 작업을 완료할 수 있어야 합니다.
스킬·참고 파일의 이름을 바꾸거나 삭제하면 본문의 선택 조건·경로도 갱신합니다.

## 검증

- 대표 요청과 범위 밖 요청을 대입해 `description`의 선택 경계를 확인합니다.
- 본문에서 조건에 맞는 참고 파일을 따라 작업을 완료할 수 있는지 확인합니다.
- 이름·설명 메타데이터와 스킬 안의 상대 링크를 검사하고, 포함한 예제는 목적에 맞게 검증합니다.

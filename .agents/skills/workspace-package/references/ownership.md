# 로직 소유권과 호환성

파일 이동·공통화·패키지 분리 전에 호출부·공개 경로·생성과 종료 지점을 확인합니다.
계약·변경 이유·자원 수명이 같은 구현을 묶습니다.

## 계약과 소비자 구분

| 관리할 계약                                        | 소유 위치          |
| -------------------------------------------------- | ------------------ |
| 여러 소비자가 지켜야 하는 업무 계산·검증·상태 전이 | 해당 도메인 모듈   |
| HTTP 상태·쿠키·터미널 안내·화면 표시               | 각 소비자 경계     |
| 특정 기능의 상태·불변식을 다루는 도우미            | 해당 기능 내부     |
| 업무 규칙 없이 설명 가능한 기술 계약               | 구체적인 기반 모듈 |
| 독립적인 소비자·의존성·배포 수명을 가진 기능       | 별도 패키지 검토   |

예를 들어 주문 가능 수량은 공통 정책이고, 초과 결과를 HTTP 오류나 화면 문구로 표현하는 책임은 소비자에게 있습니다.

```text
packages/
├── domain/src/orders/
│   ├── check-order.ts           # 주문 가능 수량 판정
│   └── schemas/order.schema.ts  # 소비자 공통 계약
├── api/src/orders/              # HTTP 입력·응답
└── web/src/orders/              # 사용자 입력·화면 표시
```

트리는 책임 배치 예시이며, 실제 경로는 기존 소유 패키지에 맞춥니다.

## 디렉터리와 의존 방향

| 책임        | 경로 예                   | 포함할 내용                                   |
| ----------- | ------------------------- | --------------------------------------------- |
| 기능        | `src/orders/`             | 정책·계약·상태와 기능 전용 연결·표현 변환     |
| 실행 조립   | `src/app/`                | 실행 설정·의존성 생성·기능 연결·시작과 종료   |
| 기술 기반   | `src/common/filesystem/`  | 기능 상태를 몰라도 설명 가능한 파일 처리 계약 |
| 테스트 지원 | 각 소유 영역의 `testing/` | 해당 자원 준비·관찰·단언                      |

경로는 필요한 책임만 구성합니다. 공통화·분리는 사용처 수보다 계약·자원 수명을 기준으로 판단합니다.

- 기반의 제품 코드는 소비 기능·실행 조립·테스트 지원에 의존하지 않습니다.
- 기능에는 필요한 실행 의존성만 전달합니다. 시작 코드·전체 모듈 등록·전역 실행 인스턴스를 가져오지 않습니다.
- 같은 상태 버전·불변식·무효화 수명을 공유하는 구현은 함께 둡니다.
- 공개 `testing` 배럴은 각 소유 영역의 외부 소비자용 API를 모읍니다.

## 이동 후 확인

1. 호출부를 새 소유 파일이나 패키지 공개 경로로 연결합니다.
2. 호환성 목적이 없는 전달 래퍼·중간 재수출·빈 디렉터리를 정리합니다.
3. 실행 스크립트·모킹·도움말·문서의 경로를 갱신합니다.
4. 공개 경로·순환 의존성·초기화 순서·자원 수명을 검사합니다.

## 호환성과 데이터 변경

프로토타입·운영이라는 이름보다 기존 소비자와 보존할 데이터를 기준으로 판단합니다.

| 조건                                                 | 처리                                              |
| ---------------------------------------------------- | ------------------------------------------------- |
| 모든 소비자를 함께 바꿀 수 있고 데이터도 재생성 가능 | 현재 계약으로 정리하고 변경 영향·초기화 방법 안내 |
| 사용자 데이터 또는 구버전 소비자가 남음              | 변환·호환 기간·실패 시 복구 방법 설계             |
| 데이터 소유자·복구 가능성이 불명확                   | 읽기 전용으로 확인하고 삭제·초기화 보류           |

호환 코드에는 대상과 제거 조건을 정합니다. 데이터 변환 후 소비자의 실제 동작을 검증합니다.

# API 계약을 설명하는 주석

API 주석을 쓰거나 중복 설명을 정리할 때 읽습니다. **입력·완료·실패·후속 행동을 결정할 계약은 소유 선언에 둡니다.** 선언·구현·호출부·테스트로 뒷받침하는 범위만 씁니다.
선언·구현·테스트가 충돌하면 차이와 근거 위치를 밝히고, 의도한 계약이 확인될 때까지 한쪽을 보장으로 단정하지 않습니다.

## 설명을 둘 위치

| 설명할 내용                                        | 위치                             |
| -------------------------------------------------- | -------------------------------- |
| 입력·기본값·결과·오류·부수 효과·소유권과 대표 예제 | 계약을 소유한 선언의 문서 주석   |
| 설치·실행·기능 조합                                | 사용 안내에서 상세 계약으로 연결 |
| 알고리즘·우회 처리의 이유                          | 구현 옆 주석                     |

이름·타입만 반복하는 설명은 생략합니다. 단위·입력 범위·기본값·완료 시점·실패 후 상태·부수 효과·승인·자원 책임 중 호출자의 행동을 바꾸는 조건은 남깁니다. 주석이 없더라도 구현으로 확인하지 못한 조건을 추정해 채우지 않습니다.

## 선언 반복과 계약 설명

| 선언을 반복하는 설명        | 필요한 계약                                                   |
| --------------------------- | ------------------------------------------------------------- |
| "제한 시간 숫자입니다."     | 밀리초 단위, 허용 범위, 기본값, 0의 의미                      |
| "사용자를 반환합니다."      | 미존재 시 null인지 오류인지, 반환값 수정 허용 여부            |
| "비동기로 저장합니다."      | Promise 이행 시 기록·전송 중 무엇이 완료되는지                |
| "연결을 종료합니다."        | 새 작업 허용 여부, 진행 중인 작업 처리, 빌린 자원의 종료 책임 |
| "스키마의 출력 타입입니다." | 선언으로 충분하면 생략. 추가 계약은 스키마·소유 선언에 배치   |

오류는 발생 조건·실패 방식·남을 수 있는 효과를 구분합니다. 비동기 완료는 호출 시작·로컬 등록·원격 확인 중 어느 시점인지 밝힙니다.

## 타입 검사 전용 예제

네트워크 구현을 생략한 가상의 TypeScript 계약입니다. 타입만 검사할 수 있으며 런타임·시간 제한·원격 기록 보장은 검증할 수 없습니다.

```ts
// message-writer.ts
export interface WriteOptions {
  /**
   * 기록 완료를 기다릴 최대 시간(밀리초)입니다. 양의 유한수만 허용합니다.
   *
   * @defaultValue `5_000`
   */
  timeoutMs?: number;
}

/**
 * 연결 하나에 메시지를 순서대로 기록합니다.
 *
 * @remarks 호출자가 각 호출의 완료를 기다린 뒤 다음 메시지를 보내야 합니다.
 */
export interface MessageWriter {
  /**
   * 메시지를 전송합니다.
   *
   * @param text - 빈 문자열을 포함해 그대로 기록할 문구
   * @param options - 대기 제한은 {@link WriteOptions}를 따릅니다.
   *
   * @returns 원격 저장소가 기록을 확인하면 이행됩니다. 별도 백업의 완료는 보장하지 않습니다.
   * @throws 대기 제한·연결 실패 시 거부합니다. 거부돼도 원격에 기록됐을 수 있으므로 재전송 전 확인해야 합니다.
   */
  write(text: string, options?: WriteOptions): Promise<void>;
}
```

계약을 바꾸는 요청에서는 같은 입력의 결과·완료 시점·실패 후 상태를 주석과 예제에 함께 반영합니다. 구현 수정이 필요한 불일치는 따로 보고합니다. 문구만 고쳐 기본값·거부 시점·재전송 안전성·자원 종료 책임을 바꾸지 않습니다.

# 스킬 작성·정제

## 남길 규칙

사용자의 명시적 선택·수정·예외와 기존 규칙에서 기본값을 찾습니다. 일반적인 도구 설명보다 **컨벤션·선택 이유·예외 조건**을 남기고, API 상세는 공식 문서로 연결합니다.

- 기본 행동을 바로 쓰고 다른 선택이 필요한 경우에만 관찰 가능한 조건과 행동을 붙입니다.
- 최신 요청이 기존 규칙을 바꾸면 정본을 갱신합니다. 적용 범위로도 충돌을 풀 수 없을 때만 질문합니다.
- 요청·기존 규칙·실제 계약에 근거하지 않은 제한이나 절차는 추가하지 않습니다.
- 행동을 정하지 않는 목적 소개·일반론, 다른 소유자의 규칙, 앞의 내용을 반복하는 요약은 삭제합니다.

예를 들어 “상황에 맞게 나눕니다” 대신 “한 구현에서만 쓰는 도우미는 그 파일에 비공개로 둡니다”처럼 산출물에서 판단할 수 있게 씁니다. 예제에는 선택을 구별할 입력·조건·결과를 남깁니다.

## 정보 배치

| 위치                 | 담을 정보                                                  |
| -------------------- | ---------------------------------------------------------- |
| `name`·`description` | 식별자, 선택할 대상·작업·상황                              |
| `SKILL.md`           | 공통 조건·기본 절차·판단 기준·완료 조건                    |
| `references/`        | 특정 조건의 상세 예제·절차; 본문에서 읽을 조건과 경로 연결 |

[스킬 선택에 먼저 제공되는 정보](https://agentskills.io/specification#progressive-disclosure)는 이름·설명입니다. 본문에 같은 사용 시점을 반복하지 않습니다.
절·표·참고 문서는 선택이나 실행 순서를 찾는 데 필요할 때만 둡니다. 모든 스킬에 같은 절을 채우지 않습니다.

## 규칙의 소유자

| 내용                                                        | 정본                              |
| ----------------------------------------------------------- | --------------------------------- |
| 선호 추출·선택 조건·본문과 참고 문서 배치·검색·설치·배포    | `apm`                             |
| 의미를 보존한 한국어 표현·용어 통일                         | `simple-korean`                   |
| 근거·독자 작업·정보 위치·중복 제거·Markdown·API 설명할 계약 | `documentation`                   |
| TS API·타입·모듈·수명·패키지·빌드·TSDoc 문법                | `typescript`                      |
| 시나리오·단언·격리·모킹·테스트 도우미·타입 단언 검증        | `testing`                         |
| 업무 규칙·상태 소유권·도메인 경계·의존 방향·공통화          | `project-structure`               |
| 커밋 메시지·승인 범위·스테이징·커밋·훅                      | `git-commit`                      |
| 저장소 고유 경로·설정·운영 정책                             | 저장소 지침·설정·소유 패키지 문서 |
| 일회성 단계·임시 경로·승인                                  | 해당 작업 기록                    |

한 규칙은 한 소유자가 관리하고 다른 스킬에는 필요한 적용 예만 둡니다. 표현 수정만 요청받았다면 기술 계약·운영 의무·기존 형식을 보존합니다.

## 경계 조정

- 필요한 요청에서 선택되지 않거나 범위 밖에서 선택되면 `description`의 대상·작업·상황을 고칩니다.
- 조건부 상세는 같은 스킬의 참고 문서로, 다른 소유자의 규칙은 그 정본으로 옮깁니다.
- 독립된 요청·절차·산출물이 있고 기존 소유자가 없을 때만 새 스킬로 나눕니다.

각 스킬은 형제 스킬·특정 저장소 문서를 필수로 읽지 않아도 담당 작업을 끝낼 수 있어야 합니다. 실제 작업의 설정·코드를 읽는 것은 허용하되, 필수 형제 호출 체인이나 형제 스킬 상대 링크는 만들지 않습니다.
이름·경로를 바꾸거나 삭제하면 해당 참고 문서를 읽을 조건과 링크도 갱신합니다.

## 확인

기본값·예외·범위 밖 요청을 대조하고 메타데이터·내부 링크·예제를 검사합니다. 근거 없는 제한·중복 소유자·필수 형제 호출이 없어야 합니다.
실제 선택 검증은 스킬명을 지정하지 않은 요청의 실행 기록에서 선택된 스킬·참고 문서·산출물을 확인합니다. 문서만 검토했다면 선택 동작은 미확인으로 보고합니다.

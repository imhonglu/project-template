# 프로젝트 구조 설계

요구사항·소비자·실행 환경과 기존 디렉터리·패키지의 책임을 확인합니다.
설계안은 책임 배치·의존 방향·공개 경로로 구체화하고, 이동·분리는 호출부와 도구 설정까지 반영합니다.

## 작업별 기준

### 책임과 패키지 경계

기능을 배치하거나 공통화·분리할 때 [책임 배치와 호환성](references/ownership.md)을 읽습니다.

| 상황                                           | 배치                             |
| ---------------------------------------------- | -------------------------------- |
| 기존 기능과 함께 변경하는 구현·검증 도구       | 소유 패키지 안의 관심사 디렉터리 |
| 같은 패키지에서 소비 목적·실행 환경이 다른 API | 별도 공개 경로                   |
| 독립적인 소비자·의존성·배포 수명               | 별도 패키지                      |

경로는 `packages/*` 또는 `apps/*`·`libs/*`·`tools/*` 등 기존 구조에 맞춥니다.
단일 패키지에서도 같은 책임 구분을 적용합니다.

### 소비자와 실행 경계

새 라이브러리는 단일 공개 진입점으로 시작하고 소비 목적·환경·전용 의존성이 달라질 때 하위 경로를 추가합니다.

| 소비자                      | 제공할 내용                     | 공개 경로 예제             |
| --------------------------- | ------------------------------- | -------------------------- |
| 제품 기능을 사용하는 앱     | 공통 타입·스키마·계산           | `@example/library`         |
| 서버에서 사용하는 앱        | 파일·프로세스 등 환경 전용 기능 | `@example/library/node`    |
| 제품을 검증하는 외부 소비자 | 재사용할 검증 API·도우미        | `@example/library/testing` |
| 명령을 실행하는 사용자      | 인수·출력·종료 코드             | 별도 실행 명령             |

실행 진입점은 인수·신호·출력·종료 정책을 맡고, 제품 모듈은 호출할 기능을 제공합니다.

### 빌드와 릴리스 소유권

독립 배포할 앱은 해당 패키지에서 산출물을 만들고, 공유 라이브러리는 소비 앱의 번들에 포함할 수 있습니다.

| 소유자                      | 책임                                                                   |
| --------------------------- | ---------------------------------------------------------------------- |
| 각 실행 패키지              | 빌드 명령·바이너리 이름·실행 진입점·전용 자산 생성                     |
| 공통 빌드 도구              | 명시한 구성의 번들·실행 파일 생성·메타데이터·실패 시 정리              |
| 특정 의존성을 사용하는 모듈 | 환경별 로더·네이티브 파일 선택 등 해당 의존성의 배포 계약              |
| 릴리스 조립 영역            | 각 패키지의 공개 빌드 명령 실행·결과 대조·전체 릴리스 취합과 설치 검증 |

공통 빌드 도구는 앱의 공개 설정·콜백을 받습니다.
이를 사용하는 앱의 개발 의존성으로 연결하고, 단순 명령 반복은 워크스페이스 실행 도구에 맡깁니다.
릴리스 조립에 독립된 의존성·진입점이 필요하면 별도 패키지로 구성할 수 있습니다.

```text
packages/
├── app/                        # 실행 진입점·앱 전용 빌드 설정과 명령
├── library/src/codec/          # 선택한 의존성의 로더·자산 준비
└── build-tool/src/             # 앱과 무관한 구성·생성 계약
scripts/release/                # 공개 빌드 명령의 실행·취합·설치 검사
```

공통 검사는 루트에서, 환경별 빌드·테스트는 해당 패키지에서 관리합니다.

## 결과 확인

### 설계안

- 소비자별 사용 경로와 모듈·패키지의 책임·의존 방향을 확인합니다.
- 분리·공통화의 근거와 기존 소비자·데이터에 미치는 영향, 미확인 조건·검증 방법을 남깁니다.

### 이동·구성 변경

- 디렉터리 이동 전후의 공개 이름·경로·명령과 [호환 조건](references/ownership.md#호환성과-데이터-변경)을 대조합니다.
- 패키지·테스트·진입점 검색 범위, import·스크립트·모킹·도움말·문서의 경로를 갱신합니다.
- 역할이 없어진 전달 래퍼·중간 재수출·빈 디렉터리를 정리하고, 순환 의존성·초기화 순서·자원 수명을 검사합니다.
- 의존성이 바뀌면 선언을 수정하고 설치 도구로 잠금 파일을 갱신합니다. 전이 의존성 변경이 빌드·검증 캐시에 반영되는지 확인합니다.
- 저장소의 전체 검사와 영향받는 소비자의 빌드·실행을 확인합니다. 전체 검사에 포함된 단계는 중복 실행하지 않습니다.
- 변경 내용·검증 결과·남은 제약을 보고하고, 기존 실패와 이번 변경으로 발생한 실패를 구분합니다.

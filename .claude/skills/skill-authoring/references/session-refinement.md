# 세션 기반 스킬 개선

## 근거 추출

현재 요청과 가장 최근의 수정·예외에서 시작합니다. 접근할 수 있는 대화·산출물·실행 기록을 사용하고, 판단에 빠진 근거만 추가로 조회합니다.

| 세션에서 찾은 근거                       | 처리                                       |
| ---------------------------------------- | ------------------------------------------ |
| 사용자가 명시하거나 반복해서 수정한 선택 | 적용 조건과 기본 행동으로 정리             |
| 에이전트가 제안했고 결과가 좋았던 방법   | 사용자 선호로 확정하지 않고 후보로 검토    |
| 특정 파일·이번 작업에만 필요한 조치·승인 | 해당 작업 기록에 유지                      |
| 도구 실패·비용 증가·품질 저하            | 원인과 재현 조건을 확인해 개선 후보로 기록 |

“좋아”는 직전 제안의 범위에서 해석합니다. 이전 커밋 승인이나 일회성 예외를 이후 작업의 상시 규칙으로 만들지 않습니다.

## 소유자와 변경 결정

관련 지침·설정을 모아 읽고 같은 결정을 맡는 정본의 기존 문장을 수정합니다. 독립 작업은 스킬로, 같은 작업의 상세는 해당 스킬의 참고 문서로 정리합니다.

긴 문장 자체를 결함으로 삼지 않습니다. 행동·조건·계약이 예제나 다른 정본에 이미 있으면 설명을 걷어내고, 빠진 판단 기준은 짧은 조건이나 예제로 보강합니다.

| 근거                                       | 반영 예                                                              |
| ------------------------------------------ | -------------------------------------------------------------------- |
| “커밋을 목적과 의도로 나눠 달라”           | 커밋 단위 문장을 수정. 같은 뜻의 금지·권장 문장을 추가하지 않음      |
| “using이 가능한데 정리용 래퍼가 필요한가?” | 테스트의 자원 수명별 선택과 예제를 수정. 제품 API의 수명 계약은 유지 |
| “TSDoc과 Markdown 참조가 섞인다”           | 언어 문법은 TypeScript, 문서 링크 형식은 문서화 지침에서 정리        |

## 결과와 다음 개선

결과는 근거·변경 이유·검증 결과·남은 문제로 요약합니다. 별도 문서는 요청되었거나 후속 작업에 필요할 때 남기고, 파일 내용은 경로·diff로 연결합니다. 배포본은 대상 환경의 도구로 재생성합니다.

의미·권한·수정 범위를 보존하며 요청한 문제를 해결했으면 유지합니다. 회귀가 있으면 해당 변경을 다시 정제·검증하고, 해결하지 못한 문제는 후속 과제로 남깁니다.

사본·해시·원시 실행 기록은 실제 전후 비교를 할 때 [평가 방법](evaluation.md)에 따라 보관합니다. 선택·효율 개선은 비교한 범위에서만 보고합니다.

# 문서 작성·정비

문서의 분야·형식에 관계없이 대표 예제와 읽는 순서를 먼저 정하고, 필요한 설명을 보완합니다. 기존 언어·용어와 해당 분야의 사실·사용 조건은 보존합니다.

## 기본 예제

사용법은 **적용 조건 → 실행 예제 → 결과·필요한 설명** 순서로 작성합니다.

전제: 루트 `test` 스크립트가 Vitest를 실행하고 `@project-template/example` 프로젝트가 등록된 구성입니다.

````markdown
# 특정 패키지 테스트하기

워크스페이스 설치를 마친 뒤 저장소 루트에서 실행합니다.

```sh
pnpm test --project @project-template/example
```

테스트가 실행되고 명령이 종료 코드 0으로 끝나면 성공입니다.

`No projects were found`가 나오면 루트의 프로젝트 검색 경로와 패키지의 테스트 설정을 확인합니다.
````

## 작업 절차

### 1. 독자·근거 확인

독자가 문서를 읽고 할 일과 확인할 근거를 정합니다. 결과를 좌우하는 정보가 부족하면 질문합니다.

| 설명할 내용         | 확인할 근거                     |
| ------------------- | ------------------------------- |
| 사용법·지원 범위    | 공개 API·명령·설정·테스트       |
| 설계·선택 이유      | 요구사항·논의·현재 구현         |
| 작업 지침·작성 규칙 | 적용할 작업·실제 절차·기존 관례 |

선택 이유는 확인된 근거로 설명하고, 사실과 추정을 구분합니다.

### 2. 대표 예제·정보 순서 설계

독자가 따라 하거나 판단할 수 있는 대표 사례를 고릅니다. 사용법은 입력·실행·결과가 드러나게 작성합니다.

| 독자가 할 일        | 읽는 순서                         | 참고 예제                                    |
| ------------------- | --------------------------------- | -------------------------------------------- |
| 프로젝트 시작       | 소개 → 최초 실행 → 관련 안내      | [루트 README](references/readme.md#루트)     |
| 특정 기능 사용      | 소개 → 사용법 → 개발              | [패키지 README](references/readme.md#패키지) |
| 절차·작성 기준 적용 | 적용 조건 → 예제 → 판단 기준·검증 | 위 기본 예제                                 |

- 예제 앞에 실행 위치·필수 설정·선행 파일을 적고, 뒤에 기대 결과를 둡니다.
- 실행 예제는 필요한 구현·설정을 제공하거나 연결합니다. 구조 설명용 예제·발췌 코드는 적용 위치와 보완할 부분을 표시합니다.
- 실제 공개 경로·명령을 사용합니다. 파일 변경·외부 요청의 효과를 밝히고 비밀값은 제외합니다.
- 순서가 필요한 작업은 단계로, 독립된 작업은 같은 위계의 절로 나눕니다.

필요한 내용을 골라 읽거나 다시 찾아야 할 때는 [탐색 안내](references/navigation.md)를 구성합니다. 주제·상황에서 해당 절로 연결하고 필요한 전제·검증도 함께 찾을 수 있게 합니다.

### 3. 설명 통합·구조 정제

소개·범위는 목적·대상·적용 조건으로 구체화합니다.

> Node.js와 브라우저에서 사용하는 메모리 저장소입니다.

경계는 유사한 기능과 혼동할 근거가 있을 때 명시합니다. 호환성 제한·실패 조건·실행·승인 제약은 정확히 남깁니다.

예제에서 드러나지 않는 이유·제약을 보완합니다. 새 정보는 관련 문장·절에 통합하고, 설명이 길어지면 구조를 다시 작성합니다.

| 읽기 어려운 상태                    | 정제 방법                                |
| ----------------------------------- | ---------------------------------------- |
| 예제와 설명이 같은 동작을 반복      | 예제를 중심에 두고 전제·이유·제약만 설명 |
| 한 문장에 동작·조건·예외가 섞임     | 핵심 문장과 조건·예외 분리               |
| 한 문단에 여러 질문의 답이 섞임     | 작업별 절로 재배치                       |
| 절차·선택 기준이 긴 문장으로 이어짐 | 순서는 번호 목록, 비교는 표로 정리       |
| 같은 사실이 여러 곳에 있음          | 정본 한 곳을 갱신하고 나머지는 연결      |

- 제목·순서는 독자가 할 일에 맞춥니다. 예제·설명·검증을 필요한 만큼 묶거나 나누고, 표·목록은 비교·선택·절차를 찾기 쉬워질 때 사용합니다.
- 버전·설정 전체는 관리 파일로 연결합니다. 사용에 필요한 기본값·제약은 원본과 대조해 설명합니다.
- 빈 절과 목적에 불필요한 내부 구현·파일 트리·의존성 나열은 생략합니다.

### 4. 변경과 문서 연결

변경된 이름·용어·규칙으로 관련 설명과 예제를 찾아 함께 갱신합니다.

| 변경                | 확인할 내용                             |
| ------------------- | --------------------------------------- |
| 공개 진입점·이름    | import 경로·호출 예제·링크              |
| 명령·설정           | 준비 조건·필수 옵션·생략 시 동작        |
| 동작·지원 범위      | 기대 결과·제약·문제 해결·이전 안내      |
| 작업 지침·작성 규칙 | 소개·적용 조건·절차·예제·참고 자료 연결 |

## 결과 확인

### 내용·구조

- 독자의 주제·요청에서 필요한 절로 이동해 적용 조건·예제·결과 또는 판단 근거를 찾을 수 있는지 확인합니다.
- 상세 계약의 누락, 반복 설명, 한 문장·문단에 몰린 조건을 확인합니다.
- 링크·제목 앵커·공개 경로를 대조하고 포맷·철자를 검사합니다. 렌더링 도구가 있으면 표시도 확인합니다.

### 예제 검증

- 변경한 실행 예제는 대상 환경에서 검사·실행하고, 타입 검사 전용 예제는 타입 검사에 포함합니다. 기존 검사에서 빠진 코드 블록은 따로 검증합니다.
- 외부 서비스·데이터 변경이 필요한 예제는 격리된 환경과 요청 범위에서 검증합니다.

변경·검증 결과와 미실행 예제·확인되지 않은 사실을 보고합니다.
